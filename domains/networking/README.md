# domains/networking/ — Networking Domain

## Purpose

Provides network infrastructure that other domains depend on:
- Caddy reverse proxy with route aggregation (subpath + port + static + vhost modes)
- Cloudflare Tunnel for public ingress (MCPs, n8n, webhooks)
- Podman media-network creation
- Gluetun VPN container for download stack
- Pi-hole DNS container
- Centralized route definitions for all services

## Boundaries

- Owns: reverse proxy config, Cloudflare Tunnel (public ingress), VPN, DNS, podman networking
- Does NOT own: individual service containers (those live in their own domains)
- Route definitions: currently centralized in `routes.nix`, will be distributed to individual domains as they migrate

Audiobookshelf's `needsUrlBase = true` carried the comment "Audiobookshelf has hardcoded /audiobookshelf/ base path" — **that was wrong**, and it is worth recording why it survived: no base path is configured anywhere (no `ROUTER_BASE_PATH` in the container env), but the SPA serves `index.html` for *any* path, so `/audiobookshelf/` returned 200 and the false claim looked verified. A 200 from an SPA proves only that something answered — the same trap as the empty-200 vhost fallthrough in the 2026-08-15 entry, arriving from the opposite direction. Homepage tile repointed in the same commit (`monitoring/homepage`); `/docs` and `/music` tiles stay until those two apps migrate.
- 2026-08-19: `sabnzbd` moved `subpath` → `vhost` — serves at `sabnzbd.hwc.iheartwoodcraft.com`, `/sab` retired. Canary for finishing the migration the 2026-08-15 entry left open, and picked first precisely because it is the worst case: it is the only remaining app carrying **both** an in-app URL base and a host allowlist, so it exercises every failure mode the others can only exercise one of. Trigger: `sab.hwc.iheartwoodcraft.com` was reported unreachable — a name that never existed, because subpath routes get no vhost name; the real URL was `<rootHost>/sab`. The app-side half cannot lag the route by even one rebuild: SABnzbd validates the `Host` header Caddy forwards (`header_up Host {host}`), so a route flip without `sabnzbd.<vhostDomain>` in `host_whitelist` answers **every** request with "Hostname verification failed" — which reads as "SAB is down" and is nothing of the sort. Both facts now derive from the same late-bound `vhostDomain` in `domains/media/sabnzbd/parts/config.nix` rather than being typed twice, so the subzone can change without an edit here. `url_base` is cleared by the same `ExecStartPre` enforcer (a stale `/sab` would 301 every request to a path the vhost does not route). Verified by **content**, not status: per the 2026-08-15 entry a missing `@name host` matcher falls through to an empty HTTP 200, so a status-code-only check is worthless here.
- 2026-08-15: **`mode = "vhost"` is now the routing standard; the *arr stack migrated off subpath.** `sonarr`/`radarr`/`lidarr`/`readarr`/`prowlarr` moved `subpath` → `vhost`, so they serve at `<app>.hwc.iheartwoodcraft.com` under the existing wildcard cert (no new DNS, cert, or port). Trigger: `radarr.hwc.iheartwoodcraft.com` *looked* live — DNS resolves via the wildcard and Caddy accepts the host into the `*.hwc.iheartwoodcraft.com` site block — but no `@radarr host` matcher existed, so it fell through to an **empty HTTP 200**. A status-code-only check passes against that; only a content check catches it (same failure mode recorded in the monitoring README's 2026-07-10 Homepage audit — worth treating as the house rule for verifying any route). The real coupling was that the URL base had **three producers** per app: `routes.nix` (`path` + `needsUrlBase` + `X-Forwarded-Prefix`), `<app>/sys.nix` (`<APP>__URLBASE` container env), and `<app>/parts/config.nix` (`urlBase` → `config.xml`). Migrating to vhost sets all three to empty and the shared literal disappears rather than moving, so there is no longer a prefix to keep in sync. Five in-repo consumers pinned the old base and were rewired in the same change: `monitoring/exportarr` (`appUrls`), `monitoring/prometheus` (5 blackbox `/ping` probes), `media/soularr` (lidarr readiness gate), and `media/recyclarr` (3 `base_url`s). One runtime consumer is **not** in the repo — Prowlarr's `Applications` table stores `http://<app>:<port>/<base>` per app; migrated by one-time SQL, see the media README. Held on subpath deliberately: `webhook`, `couchdb` (`/sync`), `mcp` — each has an external consumer pinning the URL — and `jellyseerr-subpath`, a convenience alias for a service that already has a vhost. The remaining subpath routes (navidrome, sabnzbd, qbittorrent, calibre-server, paperless, books, audiobookshelf) are un-migrated, not blocked; each needs its own in-app URL base cleared in the same commit that flips its mode.

# domains/networking/ — Networking Domain

## Purpose

Provides network infrastructure that other domains depend on:
- Caddy reverse proxy with route aggregation (subpath + port + static + vhost modes)
- Cloudflare Tunnel for public ingress (MCPs, n8n, webhooks)
- Podman media-network creation
- Gluetun VPN container for download stack
- Pi-hole DNS container
- Centralized route definitions for all services

## Boundaries

- Owns: reverse proxy config, Cloudflare Tunnel (public ingress), VPN, DNS, podman networking
- Does NOT own: individual service containers (those live in their own domains)
- Route definitions: currently centralized in `routes.nix`, will be distributed to individual domains as they migrate

- 2026-08-20: **gluetun became multi-instance** — `hwc.networking.gluetun.enable` and its flat options are replaced by `hwc.networking.gluetun.instances.<name>.*`, an attrset keyed by container name. The reason is not generality for its own sake: slskd needs to be behind the VPN *and* keep an inbound Soulseek port, and Proton forwards exactly **one** port per WireGuard session, which qBittorrent already holds on the existing tunnel. One tunnel cannot satisfy both, so the shape had to change before the leak could be fixed properly. The live tunnel is now instance `gluetun` and was verified unchanged by evaluation diff, not by inspection: container `extraOptions`, `ports`, `volumes`, `environment` and `environmentFiles` are byte-identical before and after, and every `VPN_*`/`WIREGUARD_*`/`HEALTH_*` line of the generated env file is identical (only comments moved). Its data directory is unchanged too — `dataDir = "${appsRoot}/${name}"` resolves to the pre-existing `/opt/gluetun` for the instance named `gluetun`, with no special case. Unit names were deliberately kept as `<name>-port-sync` / `<name>-health-check` so the existing tunnel's units keep their exact names. **Shape note worth keeping:** the first attempt wrote `config = lib.mkIf (instances != {}) (lib.mkMerge (mapAttrsToList ...))` and hit infinite recursion — the module system's `pushDownProperties` forces the contents of a top-level `mkIf`/`mkMerge` before `config` is fixed, so a merge list *derived from config* cannot sit there. Both parts now expose a plain attrset with literal top-level names and config-derived values, and `domains/lib/mkInfraContainer.nix` grew `mkInfraContainers` (plural) for exactly this: the singular helper returns a module fragment and cannot express a config-derived set.
- 2026-08-20: **the health check now escalates instead of retrying forever.** The old one restarted gluetun every 15 minutes for 33 hours against a peer that was never coming back and fired 43 identical alerts into #hwc-alerts in 24 hours — none dropped, all the same sentence, no transition, no give-up. That is why 33 hours passed with nobody acting; the alert stream carried no information after the first message. It is now a three-state machine per instance (`healthy`/`degraded`/`failed`) persisted in `<stateRoot>/<name>/status.json`, alerting **only on transitions** (one on degrade, one on give-up, one on recovery — a 33-hour outage is 2 messages), with restarts on a bounded backoff ladder (15m→30m→1h→2h→4h capped) instead of a fixed 15-minute loop. It never stops retrying, because a transient drop must still self-heal, but after `escalateAfterRestarts` failures it says so once at priority 1 and then goes quiet. Sustained degradation reaches the morning briefing through `status.json`, which is the actual fix for the human half: an alert at 21:00 that is still true at 06:00 has been silent all night by design, and the briefing is where Eric looks. The probe also gained an authoritative liveness check (`/v1/publicip/ip`) — during the outage the control API was reachable the whole time, so "the container is up" was never the question, and `wg show` reading `0 B received` had nothing watching it.

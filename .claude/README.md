# Claude Code project setup

Project-level Claude Code configuration for this repo.

## Slash Commands

- `/build` - Build NixOS config and check for errors
- `/check` - Run comprehensive syntax and validation checks
- `/cp` - Commit AND push in one operation
- `/status` - Show git status with unpushed commit warnings
- `/update` - Update flake inputs and verify build

To add one, create `.claude/commands/<name>.md`.

## MCP Servers

`.mcp.json` is generated by Nix on every host: a symlink into the store,
created by `hwc.system.apps.agent-harness.projectMcp`
(`domains/home/apps/agent-harness/sys.nix`) at each system switch. Do not
edit it by hand — the next switch replaces it.

- Shared servers: `fetch`, `git`, `github`, `memory`, `sequential-thinking`,
  `time`, and `hwc-sys`.
- `hwc-sys` is the Nix-built MCP gateway service (`domains/system/mcp`),
  reached over its tailnet route (`hwc.system.mcp.url`). It serves the
  system, JobTread, n8n and CRM tools, so every session on every host gets
  the deployed code.
- `github` reads its token from `gh auth token` at launch; run
  `gh auth login` on a host where it fails.
- Host-only servers go in `projectMcp.extraServers` in the machine config
  (hwc-server adds `filesystem`, `postgres`, `puppeteer`).

`settings.json` sets `enableAllProjectMcpServers`, so the generated servers
need no per-host approval.

## Git hooks

`.githooks/` is the hooks directory on every host (`core.hooksPath`, pinned
by `hwc.home.core.repoHooks`): `pre-commit` runs the charter checks,
`post-commit` pushes, `post-checkout` keeps the primary checkout on a branch.

## Files

- `commands/*.md` - Slash command definitions
- `hooks/enforce-tools.sh` - Tool-use guard
- `settings.json` - Project settings (plugins, MCP approval)
- `FAILURE-ANALYSIS.md` - Past failure notes
